# Vendored Speckit Skills

## Bundled skeleton (`skeleton/`)

`skeleton/` (templates/, scripts/, memory/) is vendored from
[github.com/github/spec-kit](https://github.com/github/spec-kit) (MIT License,
© GitHub, Inc.), generated by the `specify` CLI **v0.16.4** (`specify init
--here --script py`).

> **It is no longer the initialization source as of v0.9.** Workspace init now
> runs the official `specify init`, pinned by the plugin
> (`SPECIFY_CLI_VERSION`), because only the official flow writes `workflows/`,
> `integration.json`, `integrations/`, `init-options.json` and
> `.specify/.gitignore`. Without them spec-kit does not recognize the project's
> SDD workflow (`specify workflow list` reports `No workflows installed.`).
> Omitting that metadata from the vendored skeleton was a mistake.
> `skeleton/` now only backs the offline "reset to template" default for the
> constitution.
>
> Note: this skeleton's templates/scripts had their command prefix hand-edited
> to `/speckit-*`, which disagrees with the `$speckit-*` used by upstream and by
> the plugin's own bundled skills. Official init no longer introduces that
> divergence.

These 10 `SKILL.md` files are vendored from
[github.com/github/spec-kit](https://github.com/github/spec-kit) (MIT License,
© GitHub, Inc.), as generated by the `specify` CLI v0.16.4 in Codex skills
mode (`specify init --here --integration codex --integration-options="--skills"`).

| Skill directory | Workflow phase |
|---|---|
| `speckit-specify` | specify |
| `speckit-worktrees-create` | worktrees |
| `speckit-clarify` | clarify |
| `speckit-plan` | plan |
| `speckit-checklist` | checklist |
| `speckit-tasks` | tasks |
| `speckit-analyze` | analyze |
| `speckit-taskstoissues` | taskstoissues (optional) |
| `speckit-implement` | implement |
| `speckit-converge` | converge |

`speckit-constitution` is vendored as of v0.8.2 — it backs the standalone
Constitution page, which sits outside the stage chain. `speckit-worktrees-clean`
and `speckit-worktrees-list` are intentionally not vendored: they are
interactive maintenance tools, not pipeline phases.

At run start the plugin materializes these files under the target project's
`.dsh/speckit-workflow/skills/` (hash-verified, re-synced on plugin upgrade),
so phase agents read skills from a stable project-relative path — never from
the package's install location. Official `specify init` additionally writes a
byte-identical copy into the project's `.agents/skills/` (its Codex
integration output); the plugin never reads from there.
