> 配套工程：`placegame-vip-client/`（Tauri v2 + Rust + SQLite + 静态 Web UI）

## 1. 收菜逻辑

### 1.1 总体流程图

```
后台调度器（每 30s tick，daemon 常驻）
│
├─ 对每个"启用"账号执行 process_account（DB 判断"该不该做"，网络只在需要时打）
│
│  主账号(main)：
│    ├─ 今日未被收 → collect_round(with_daily=true)   # 每日一轮
│    ├─ 否则按容量调度：next_collect ≤ now → collect_round(with_daily=false)
│    ├─ 公会：今日未审批 → 审批待入会申请；今日未分红 → 领公会分红
│
│  小号(alt) 状态机：
│    ├─ ""      → 建角色 → phase=init
│    ├─ init    → 每 5 分钟练级一次（换图+收挂机经验）→ 到 12 级 → phase=ready
│    ├─ ready   → 申请入会（免审核）→ 成功 → phase=joined
│    └─ joined  → 每日捐献背包材料（run_key=donate:今日）
│
└─ 全部写入 runs 表（幂等）+ meta（next_collect / phase / 节流时间戳）
```

### 1.2 调度模型（三个节奏，各管各的）

| 节奏 | 触发 | 实现 |
|---|---|---|
| 挂机收益 | **容量 90%**（默认 12h×0.9≈11h）后才收 | 每轮收完写 `meta.next_collect:{id}` = now + 容量×90%，下轮判断 `next_collect ≤ now` |
| 每日日常 | 北京日（`daily.key` 同口径，UTC+8）每个任务一次 | `runs(account_id, task, run_key=daily:{北京日期})` 存在即跳过 |
| 小号练级 | 每 5 分钟最多一次 | `meta.alt_level_last:{id}` 节流，避免 30s tick hammering |

### 1.3 一轮收菜（collect_round）的完整顺序

顺序有讲究：先资源后结算，避免加成没吃上。

```
1. ensure_session           # 会话保活：users/list 探活；过期→用本地凭证自动重登
2. GET /api/client/bootstrap  # 全量状态，取 daily.key（北京日）+ 各可领标记
3. POST /api/mail/claim-all   # 邮件（新号福利/每日登录/市场到账）
4. POST /api/mail/delete-read # 清理已读
5. [仅每日轮] POST /api/retention/sign-in          # 今日未签才签
6. [仅每日轮] POST /api/daily/claim {point}        # 7 个活跃点，重复领自动忽略
7. [仅每日轮] POST /api/achievements/claim {key}   # 遍历 unlockedKeys
8. GET  /api/client/idle-summary                   # 有货才收
9. POST /api/client/collect                        # 领挂机收益；若返回 adventure
   └─ POST /api/client/collect {adventureOptionKey}  # 旅途奇遇自动择一结算（最多一轮）
```

### 1.4 幂等与并发（为什么重跑安全）

- **服务端天然幂等友好**：挂机收益是累计结算（重收只拿 0）；邮件/签到/宝箱重复点返回"已领"。
- **本地再加一层**：`runs` 表主键 = `(account_id, task, run_key)`，`INSERT OR REPLACE`；`run_key` 按北京日/时间戳构造 → 任务只能发生一次。
- **防重入**：`Shared.pass_busy` 原子标志，后台 tick 与"立即同步一轮"互斥，不会双跑。
- **挂机收益特殊**：先 `idle-summary` 判断有货才 `collect`；失败就留到下一轮（收益在服务端不丢，唯一真风险是超 12h 容量上限——所以用 90% 提前量）。

### 1.5 错误与自愈

| 情况 | 处理 |
|---|---|
| 会话过期（401/403 "会话无效或已过期"） | 自动用本地账号密码重登（`POST /api/auth/login`）后重放 |
| 426 版本过低 | 报错记录到 runs，提示升级客户端 |
| 503/维护 | 本轮失败，下轮自动重试（不硬顶） |
| 网络抖动 | 探活失败沿用旧 token，本次操作失败由下轮补 |
| 任意单步失败 | 只影响该账号该任务，不中断整轮；runs 表记 failed + 原因 |

### 1.6 小号公会流水线状态机

`meta.alt_phase:{id}`，共 4 态：

| 阶段 | 触发动作 | 进入下一态条件 |
|---|---|---|
| `""`（初始） | `POST /api/character/create {nickname,job}` | 创建成功 → `init` |
| `init`（练级） | `level_once`：换最优图 + 收挂机经验（5 分钟节流） | `player.level ≥ 12`（`joinRequiredLevel`）→ `ready` |
| `ready`（待入会） | `POST /api/guild/apply {guildId}` | `guild.joined = true` → `joined` |
| `joined`（养号） | 每日 `POST /api/guild/donate {itemId, amount}` | 每日一次（run_key=donate:今日） |

- 捐献范围：**背包里 未绑定 + 未锁定 + 材料类（itemType=material）+ 不在保留列表** 的物品全量捐献。
- 保留列表默认：`boss_ticket / strengthen_stone / advanced_stone / protect_charm`（给小号留门票/强化石）。
- 大号侧：每日审批（`application/approve`）+ 每日领分红（`claim-dividend`），同样 run_key 幂等。

## 2. 接口（客户端实际调用）

> 协议与线上前端完全一致（前端逆向 + 线上实测 guest/bootstrap/catalog 三条链路）。

### 2.1 通用约定

**Base URL**：`https://game.placegame.cn`

**请求头**：

| Header | 值 |
|---|---|
| `content-type` | `application/json` |
| `x-placegame-client-version` | `0.2.49` |
| `x-placegame-client-platform` | `web`（与线上前端同平台标识） |
| `x-placegame-device-id` | 本机一次性生成并持久化（localStorage/DB，固定不变） |
| `x-placegame-web-build-revision` | `20260825.1` |
| `x-placegame-response-state` | `full` / `patch` / `omit`（见下） |
| `authorization` | `Bearer <sessionToken>`（登录后） |

**responseState 语义**：

| 值 | 用途 | 返回 |
|---|---|---|
| `full` | 登录/注册类 | `{data:{sessionToken,...}, state:{全量}, user}` |
| `omit` | 纯查询/无脑动作 | `data` 即业务结果（bootstrap 的 `data` 即整个 state） |
| `patch` | 业务变更 | `{data:{result, statePatch, 额外字段}, changedSections}` |

**状态码/错误**：`426`=版本过低；`401/403`+error 含"会话无效或已过期"=掉线；`503`=维护；`>=500`=服务器异常。

### 2.2 已实现接口清单

| 方法 | 路径 | 请求体 | responseState | 用途 |
|---|---|---|---|---|
| POST | `/api/auth/guest` | `{}` | full | 自动注册游客小号（实测可用，返回 sessionToken+generatedCredential） |
| POST | `/api/auth/login` | `{username,password}` | full | 正式账号登录 / 自动重登 |
| GET | `/api/users/list` | - | omit | 会话探活 |
| GET | `/api/client/bootstrap` | - | omit | 拉全量状态（32 sections），取 daily.key/可领标记/等级 |
| GET | `/api/client/idle-summary` | - | omit | 挂机收益预览（有货才收） |
| POST | `/api/client/collect` | `{}` 或 `{adventureOptionKey}` | patch | 领取挂机收益（含旅途奇遇） |
| POST | `/api/mail/claim-all` | `{}` | omit | 一键领邮件附件 |
| POST | `/api/mail/delete-read` | `{}` | omit | 清理已读邮件 |
| POST | `/api/retention/sign-in` | `{}` | omit | 每日签到 |
| POST | `/api/daily/claim` | `{point}` | patch | 领活跃宝箱（point: collect/kill/boss/enhance/decompose/market_list/market_buy） |
| POST | `/api/achievements/claim` | `{achievementKey}` | patch | 领成就奖励 |

| POST | `/api/battle/change-map` | `{mapKey}` | patch | 小号练级换最优图 |

| POST | `/api/guild/application/approve` | `{userId}` | patch | 大号审批入会（多候选字段兼容） |

| POST | `/api/guild/claim-dividend` | `{}` | patch | 大号领公会分红 |

## 3. 本地数据存储（SQLite schema）

文件：`~/Library/Application Support/cn.placegame.vipclient/vip.db`

```sql
CREATE TABLE accounts(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  role TEXT NOT NULL DEFAULT 'alt',          -- main | alt
  username TEXT NOT NULL, password TEXT NOT NULL,
  user_id TEXT NOT NULL DEFAULT '',
  nickname TEXT NOT NULL DEFAULT '', job TEXT NOT NULL DEFAULT 'warrior',
  device_id TEXT NOT NULL DEFAULT '',
  session_token TEXT,                        -- Bearer token（明文，量产前换 Keychain）
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL
);
CREATE TABLE runs(                           -- 任务的幂等记录
  account_id INTEGER NOT NULL, task TEXT NOT NULL, run_key TEXT NOT NULL,
  status TEXT NOT NULL, detail TEXT NOT NULL DEFAULT '',
  started_at INTEGER NOT NULL, finished_at INTEGER NOT NULL,
  PRIMARY KEY(account_id, task, run_key)
);
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- meta 常用键：device_id / main_guild_id / next_collect:{id} / alt_phase:{id} / alt_level_last:{id}
```
