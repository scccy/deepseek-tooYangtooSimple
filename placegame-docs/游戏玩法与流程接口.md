## 1. 游戏概述

- 名称：**复古打宝任务栏挂机**（占位/代号，非正式名；页面标题即此）。
- 类型：**AI 挂机（放置）打宝 RPG**。角色离线/在线自动挂机战斗、掉落装备与材料，玩家负责换图、配装、养成、交易、公会与副职经营。
- 特色：桌面客户端可**缩小到任务栏小窗/托盘**继续挂机结算，任务栏桌宠（职业小宠物）展示挂机状态；网页版登录后同样后台结算。
- 三职业：战士、法师、召唤师，各有独立技能树 + 通用技能树。
- 单人/社交并存：个人养成 + 世界聊天 + 玩家交易/求购 + 公会 + 排行赛季 + 全服协作首领。
- 经济：金币（主货币）、元宝（珍贵货币，由元宝碎片合成）、公会币、全服币、皇冠币（街机代币）等。

## 2. 客户端形态与窗口模型

| 窗口状态 `windowState` | 说明 |
|---|---|
| `main_window` | 主游戏窗口 |
| `taskbar` | 任务栏小窗（桌宠挂机视图） |
| `tray` | 托盘挂机（隐藏） |
| `mini` | 迷你窗 |
| `closed` | 关闭（挂机仍结算） |

- 网页端通过 `window.desktopBridge` 不存在时，走内嵌 HTTP 代理桥（`baseUrl = window.location.origin`）。
- 桌面端（`window.desktopBridge.isDesktop === true`）提供：`requestGameApi`、`uploadAvatar`、`sendWorldChatImageMessage`、`resolveAssetUrl`、`onGameStateChanged`、`onConnectionChange`、`setMarketSubscription`、`sendMapEvent`、`setWindowState`、`onWindowStateChanged`。
- 窗口状态变更时前端会同步调用 `POST /api/client/window-state`。
- **挂机结算不依赖窗口**：离线与在线收益默认最多累计 **12 小时**（`idleRewardCapacityHours`），隐藏到托盘/关闭窗口也会结算。

## 3. 核心玩法

### 3.1 角色与职业

- 创建角色：选**昵称** + **职业**（`POST /api/character/create`，body `{nickname, job}`）。
- 职业：`warrior` 战士 / `mage` 法师 / `summoner` 召唤师。
  - 战士：物理近战，技能从「烈斩」起步，终极「天崩斩」。
  - 法师：法术远程，技能从「火球术」起步，终极「星陨术」。
  - 召唤师：召唤物协同，技能从「召狼术」起步，终极「万兽奔袭」。
- 通用技能树：攻击专精 / 资源增幅 / 生存专精 / 暴击精通 / 挂机精通 / 掉落精通 / 通用收益精通 → 终极「命运轮转」。
- 培养：技能书掉落学习技能，技能残页升级技能（`POST /api/skills/upgrade`，body `{skillKey}`）。
- **转生（Rebirth）**：`POST /api/character/rebirth`，body `{focus}`（加成的定向选择）。转生后等级重置为 1 级，**装备、技能、货币保留**，获得永久加成（转生次数显示在角色面板）。
- 修改昵称：首次免费，后续消耗 1 元宝（`POST /api/character/nickname`）。

### 3.2 挂机战斗（核心循环）

- 玩家选择一个地图后角色**自动战斗**：按「挂机效率」每分钟击杀 N 只怪物，产出经验、金币、装备/材料掉落。
- 收益类型：经验、金币、掉落件数、元宝碎片，受 **挂机效率属性** 与 **地图强度** 影响。
- **收益累计上限 12 小时**，超过上限不再累计（离线/在线一致）。
- 领取/结算：
  - 预览：`GET /api/client/idle-summary`（返回 exp/gold/killCount/dropCount/rareCoinFragments/efficiency 等预览）。
  - 领取：`POST /api/client/collect`（空 body 或 `{adventureOptionKey}`）。
  - 领取时可能触发「**旅途奇遇**」：弹出剧情事件，给出多个增益/后果选项，选择后立即结算本次挂机收益（奇遇不重复出现）。
  - 其他客户端（桌面/托盘）推送收益用 `POST /api/battle/idle-collect`（二者都会触发本地收益预览刷新）。
- 等级达上限（`maxLevel`）后可转生。

### 3.3 地图

- 地图列表来自服务端状态 section `maps`，含：进入等级、进入战力、怪物压力、挂机效率、主要怪物、掉落材料、随机奖励、推荐战力。
- 换图：`POST /api/battle/change-map`，body `{mapKey}`（战力/等级不足不可进入）。
- 每个地图决定掉落材料池与怪物强度，越高级地图收益与压力越高。

### 3.4 掉落与保底

- 掉落判定：挂机时按 `dropBonus` 爆率判定装备/材料掉落；掉落后再按 `rareDropBonus` 向更高品质上浮。
- 元宝碎片保底：**挂机击杀每 500 次保底 2 个元宝碎片**；普通掉落、个人/地图首领、世界首领、每日活跃、签到、成就、任务、图鉴、赛季排名、系统邮件均可获得 `rareCoinFragment`。
- **元宝碎片满 100 自动合成 1 元宝**；世界首领单场最多 140 个有效碎片；个人/地图首领每日共享上限 200 个有效碎片。
- 装备分解与市场交易也会产出金币/元宝。

### 3.5 装备系统

**品质（由低到高）**：普通 → 优秀 → 精良 → 稀有 → 史诗 → 传说 → 神话（另见 front 常量 `white/green/blue/purple/orange/red/gold`）。

**部位（10）**：武器、衣服、头盔、项链、手镯、戒指、腰带、鞋子、护符、勋章（slot key：`weapon/armor/helmet/necklace/bracelet/ring/belt/boots/talisman/medal`）。

**属性（20）**：生命 hp、攻击 attack、魔攻 magicAttack、召唤 summonAttack、防御 defense、魔防 magicDefense、命中 hit、闪避 dodge、暴击 crit、爆伤 critDamage、攻速 attackSpeed、幸运 luck、经验 expBonus、金币 goldBonus、爆率 dropBonus、极品掉率 rareDropBonus、首领掉落 bossDropBonus、吸血 lifesteal、首领伤害 bossDamage、挂机效率 idleEfficiency。

**装备数据**：`装备Lv` 等级要求、基础属性（可强化）、洗炼属性（额外词条）、强化等级（+N）、评分（成色评分/穿戴评分）、绑定状态、锁定状态。

**养成动作（均为 POST 变更接口，返回 statePatch）**：

| 动作 | 接口 | 请求体要点 |
|---|---|---|
| 穿戴 / 脱下 | `/api/equipment/wear` / `take-off` | `{equipmentId}` |
| 锁定 / 解锁 | `/api/equipment/toggle-lock` | `{equipmentId}` |
| 强化 | `/api/equipment/enhance` | `{equipmentId, useProtectCharm}`（保护符） |
| 洗练 | `/api/equipment/reforge` | `{equipmentId, lockedStats[], targetStat}`（锁定词条 + 目标词条保底） |
| 升品 | `/api/equipment/quality-upgrade` | `{equipmentId}` |
| 词条继承 | `/api/equipment/affix-inherit` | `{targetEquipmentId, sourceEquipmentId}`（来源销毁） |
| 强化继承 | `/api/equipment/enhance-inherit` | `{targetEquipmentId, sourceEquipmentId}`（失败摧毁目标，消耗元宝） |
| 分解 | `/api/equipment/decompose` | `{equipmentIds[]}` |
| 解绑（可交易化） | `/api/equipment/unbind` | `{equipmentId}`（消耗交易封印 xN） |
| 一键分解（规则） | `/api/equipment/auto-decompose` / `auto-decompose-rules` | `{}` / `{patch}` |
| 上架出售 | `/api/market/create-order` | 见市场节 |

- 预览类（操作前弹窗）：`enhance-preview`、`reforge-preview`、`decompose-preview`、`quality-upgrade-preview`、`affix-inherit-preview`、`enhance-inherit-preview` 均为 **POST**，body 与对应操作一致。
- **套装**：穿戴同名套装按件数激活档位加成（`套装 X/Y 件效果`）。
- **装备套装配置（Loadout）**：支持多套配置购买（元宝）与一键切换（`/api/equipment/loadouts/purchase`、`/api/equipment/loadouts/switch`）。
- 战力 = 综合基准（等级/装备基础/强化/洗炼/套装战斗属性），**由短板主导，强项最多额外贡献短板的 25%**；收益评分 = 经验/金币/掉落/稀有掉落/挂机效率/幸运，不计入战斗战力。

### 3.6 技能系统

- 技能树按职业分支 + 通用分支组织，节点需前置且消耗技能书/技能残页/金币解锁升级。
- 战斗中自动按配置施放：普通攻击 + 3 个主动技能槽 + 被动。
- 技能书分：战士/法师/召唤师技能书、通用技能书（掉落来源：挂机/活动）。

### 3.7 副职业与补给

- 四种副职业共用一条**执行队列**（`schemaVersion:3`，`selectedProfessionKey`）：
  - `herbalism` 采药、`fishing` 钓鱼、`cooking` 烹饪、`alchemy` 炼金。
- 每个副职业有等级/经验/累计动作数；动作分“稳定采集”与“加工”（需前置原料）。
- **永久专精**：可永久专精一种副职业，耗时缩短、经验提高，不可更改；其他副职业按基础效率运行。
- 队列：`/api/professions/queue/enqueue {actionKey,count}`、`move {entryId,direction}`、`cancel {entryId}`、`clear`、以及 `POST /api/professions/settle`（收取进度/结算）。
- 离线执行受角色挂机容量限制，不改写主流程战斗时间。
- **补给（Supplies）**：
  - 挂机口粮 `foodKey`：有效挂机期间自动消耗；基础口粮 2 小时、高阶盛宴 4 小时；领取主战斗挂机收益时自动扣除。
  - 首领药剂 `bossPotionKey`：正式首领战开场自动消耗 1 瓶，胜负均消耗；提供金币+/伤害+/减伤+/破盾+ 加成。
  - 装备接口：`POST /api/professions/supply/equip`，body `{supplyType, itemKey}`（`supplyType: "food" | "bossPotion"`）。

### 3.8 货币体系

| 货币 | 说明 |
|---|---|
| 金币 gold | 普通货币：挂机收益、日常奖励、市场出售、装备分解；用于强化/洗练/金币市场交易 |
| 元宝 rareCoin | 珍贵货币（碎片满 100 自动合成 1 元宝）；各来源 + 市场交易；用于高级养成/兑换/改名 |
| 元宝碎片 rareCoinFragment | 上述保底与多来源产出 |
| 公会币 guildCoin | 公会代币（推币机等产出） |
| 全服币 worldCoin | 全服协作代币 |
| 皇冠币 crownCoin | 街机代币（推币机高价值区） |

### 3.9 首领（Boss）

- 三类：**个人首领**（`personal`）、**地图首领**（`map`）、**世界首领**（`world`，定时场次 + 全服协作）。
- 挑战消耗：**首领门票 x1（首领挑战券/首领门票 item）**；失败返还挑战机会；可「门票追加」「共享免费」等。
- **战前部署/推演**：配置出战技能、战术配置（输出优先/生存优先/均衡）、战前增益、挑战词缀、定向部位（仅本次）、材料加成（养成资源 +35%、定向装备品质提升一级）等；`POST /api/boss/preview` 返回**推演结果**（可胜/危险、剩余生命、输出/生存/综合评分）。
- 正式挑战：`POST /api/boss/challenge`，body `{bossKey, ...config}`；服务端返回 `battle.events`，前端按帧回放战斗动画，结束后依据 `notices` 弹出结算（掉落、碎片、门票返还等）。
- **世界首领协作**：活动时间（北京时间）内，`POST /api/boss/assist {bossKey}` 消耗 1 张首领门票提交一次**全服共享伤害**；参与必得基础奖励，结束后按讨伐进度、贡献档位、排名统一邮件结算；每场参与次数有限；首领有护盾/狂暴/二阶段机制，前端渲染协作状态（剩余生命、参与数、我的伤害、我的排名）。

### 3.10 市场

- 三个分区：**玩家交易**（在售商品/求购大厅/我的挂单）、**系统行商**（NPC 商店）、**元宝兑换**。
- 玩家交易（自由市场）有**等级/战力门槛**（`marketAccess`），未达标显示“自由市场交易尚未开放”。
- 出售挂单：`POST /api/market/create-order`，body `{itemType: "equipment"|"item", equipmentId|itemId, amount, currencyType, price}`。
- 求购挂单：`POST /api/market/create-buy-order`（发布即冻结预算 `frozenBudget`，取消原额退回）；交付 `POST /api/market/fulfill-buy-order {orderId, amount}`。
- 购买：`POST /api/market/buy {orderId, quantity}`；改价 `update-price {orderId, price}`；取消 `cancel {orderId}`；批量查状态 `POST /api/market/order-statuses {orderIds}`。
- 列表：`GET /api/market/my-orders?status=active`；市场查询 `GET /api/market/orders`（带 query：`scope/orderType/sort/limit/cursor/currencyType/quality/itemType/equipmentSetKey/slot/equipmentLevel/rareOnly`）。
- 报价：`POST /api/market/equipment-quote {equipmentId}`、`POST /api/market/item-quote {itemId, amount}`（返回推荐价/近期趋势/最低均价最高）。
- 规则：绑定不可交易；市场购入后 **转售锁定期**（购买后 N 小时内不可转售），解锁后转售手续费更高；成交收取手续费，货款可**延迟到账**（风控）。
- 系统行商：`GET /api/npc-shop/items`、`POST /api/npc-shop/buy {shopItemKey, quantity}`；包含“新增装备套装（元宝永久解锁）”等。
- 元宝兑换：`/api/npc-shop/items` 返回兑换列表。
- 订单可分享到世界聊天（嵌入 marketOrderId）。

### 3.11 公会

- 创建：`POST /api/guild/create {name, motto}`（费用、等级要求）；申请 `apply {guildId}`；审批 `application/approve|reject {userId}`；入会策略 `join-policy {requiresApproval}`。
- 角色：会长 / 管理 / 成员；`member-role {userId, role}`、移交 `transfer {userId}`、踢人 `kick {userId}`、弹劾 `impeach`、解散 `dissolve`、退出 `leave`。
- 资产：**公会基金**（捐献物资/材料产生）、**共享仓库**（装备仓库，可扩建 `equipment-storage/expand`；成员捐献未绑定未锁定装备，`equipment/donate {equipmentId}`，`equipment/redeem {equipmentId}` 兑换，最低入库品质可由会长设置 `equipment-donation-quality {minimumQuality}`）。
- 成员需求报表：`material-request {itemKey, amount}` / `cancel {requestId}` / `fulfill {requestId, amount}`（会长/管理用基金补充）。
- 捐赠：`guild/donate {itemId, amount}`（贡献 + 公共基金 + 分红权）；每日分红 `claim-dividend`；捐献进度里程碑 `claim-progress {point}`。
- 增益/祝福/补给：`benefit/upgrade {benefitKey}`（生命/攻击/金币收益/掉落加成）、`blessing/activate {blessingKey, days}`（激活后 24h 有效，可续费顺延）、`supply/purchase {supplyKey, count}`（每日北京时间 12:00 补货，会长可采购）。
- 其他：公告 `announcement {content}`、头像 `POST /api/guild/avatar`、筹资目标 `fund-goal {title, target}`。

### 3.12 活动中心（日常）

- 入口「活动目录」含：日常事务（今日活跃/任务/签到/图鉴）、街机娱乐（旋转/寻宝/21点/推币机）、大乐透。
- **今日活跃 / 活跃值**：完成每日目标获得活跃值，解锁「青铜/白银/黄金/赤金/神话活跃箱」；`POST /api/daily/claim {point}`。
- **每日目标**（`daily` section，按北京日期）：挂机收益领取、挑战个人首领、强化装备、分解装备、市场上架、市场购买、击杀怪物等（collectCount/bossCount/enhanceCount/decomposeCount/marketListCount/marketBuyCount/killCount）。
- **签到**：`POST /api/retention/sign-in`，每 7 天循环奖励、连续签到（`retention` section 含 signIn + pity 保底计数器）。
- **任务**：主线支线任务链，`POST /api/quests/claim {questKey}`。
- **成就**：里程碑成就，`POST /api/achievements/claim {achievementKey}`。
- **图鉴**：收集图鉴（装备模板/物品/首领），`POST /api/codex/claim {rewardKey}`。
- 掉落保底（pity）：品质保底、装备击杀进度、元宝碎片击杀进度、强化失败保底（装备升级失败计数）。

### 3.13 街机与小游戏（arcade）

每个小游戏都有**每日免费次数 + 金币付费局**，`actionId` 为活动动作标识，金币档位可选 100/500/1000/2500/5000，步进 100：

| 游戏 | 玩法 | 接口（body 均含 `actionId`，金币局含 `betGold`） |
|---|---|---|
| 地精老虎机 slot | 三转轴，三同图案大奖（巨龙2w/王冠1.2w/宝石8k/宝箱5k/幸运草4k/长剑3.5k/药剂2.5k/骷髅2k/史莱姆1.5k），对子 1100 | `slot/spin` |
| 翻牌寻宝 treasure | 6 张牌藏 2 处塌方，翻到塌方丢失暂存，可收手带走；奖励值 400/700/1200/1900 | `treasure/start`、`treasure/reveal {cardIndex}`、`treasure/collect` |

## 4. 核心流程（时序）

### 4.1 启动与登录流程

```
打开页面
  └─ 初始化玩法服务（Gameplay Service）：
       桌面端: desktopBridge.requestGameApi / onGameStateChanged ...
       网页端: 内嵌 HTTP 代理桥 xj({baseUrl})  + 自动重连
  ├─ GET /api/users/list          → 本机已登录账号列表 {users[], currentUserId}
  ├─ GET /api/client/bootstrap    → 全量状态快照 {state, changedSections}（仅无 player 时走登录，登录后再次 bootstrap）
  └─ 登录分支（无账号时）：
       ├─ 游客模式:  POST /api/auth/guest                     → 生成临时账号 {generatedCredential}
       ├─ 正式账号:  POST /api/auth/login {username,password} → {sessionToken, currentUserId}
       ├─ 注册正式账号: POST /api/auth/register {username,password}(推测)
       └─ Linux DO:
            POST /api/auth/linuxdo/start {mode:"login"|"register"|"bind"} → {authorizationUrl}
            弹窗 OAuth 完成后 postMessage 回传
            POST /api/auth/linuxdo/register|bind {ticket, username, password}（未绑定账号时）
  └─ 登录后: 再次 GET /api/client/bootstrap → 进入角色创建/主界面
       创建角色: POST /api/character/create {nickname, job}
```

### 4.2 实时通道（WebSocket）建立

```
1. POST /api/auth/ws-ticket        （body "{}"，带 Bearer）→ {ticket}
2. new WebSocket(ws(s)://host/ws?ticket=<ticket>&clientVersion=0.2.49&clientPlatform=web&webBuildRevision=20260825.1)
3. 打开后：
   - 若开启市场订阅 → send {"type":"market:subscribe"}（/ unsubscribe）
   - 客户端其他事件推送 → send {"type": "...", data: {...}}（sendMapEvent，桌面用）
4. 服务器下行：状态补丁（state patch）、世界聊天新消息、聊天撤回、世界首领实例更新、
   市场订单推送等；客户端 onmessage 解析后合并进本地状态并刷新相关 section。
5. 降级：WS 不可用时自动切到“轮询同步”模式（市场订单每 30s、首领每 15s 轮询等）。
```

### 4.3 状态同步机制（核心：section + etag + statePatch）

这是本项目最有特点的部分，前端所有读写都围绕同一份全量状态：

```
客户端状态（big state）按“section”组织：
  profile / maps / skills / bosses / quests / achievements / codex / arcade /
  professions / marketAccess / marketOrders / guild / rankingSeason / navigation /
  tradeLogs / riskEvents / currencyLogs / craftLogs / notices / mails / daily / guildDaily / retention ...

读取流程：
  GET  /api/client/bootstrap                             → {state 全量, changedSections}
  POST /api/client/view-sections {sections:[...], sectionEtags:{section:etag}}  → 各 section 数据 + 新 etag
     前端按当前视图(overview/maps/inventory/...)只拉需要的 sections；
     本地缓存 etag，服务端返回的 sectionEtags 仅在 etag 变化时客户端才视为有更新。

变更流程（写操作）：
  POST /api/<module>/... 每个变更接口都带请求头 x-placegame-response-state: patch
  → 响应: {result, statePatch, changedSections}
  前端把 statePatch 合并进本地状态，同时依据 changedSections 刷新相应 section；
  部分“关键变更”接口（见 Xj 集合，如换图/领取/强化/转生/创建公会等）还会额外刷新挂机收益预览。

订阅（多人协作增量）：
  WS/桥接推送的新状态与本地 diff 出变化的 section key → 对缺失/变化的 section 调 view-sections 增量刷新，
  相邻玩家操作（市场成交、世界聊天、世界首领血量）可近乎实时表现在界面上。
```

- 响应头 `x-placegame-response-state` 取值：`full`（登录/引导时返回全量 state）、`patch`（变更接口返回 statePatch）、`omit`（纯查询只回 data）。
- 请求带 `userId`/`sessionToken`，服务端通过会话校验归属。

### 4.4 挂机主循环

```
定时器（前端 ~15s 一次）:
  距上次收益推送 >35s 时 → GET /api/client/idle-summary 刷新收益预览
领取:
  POST /api/client/collect
    ├─ 若返回 adventure（旅途奇遇）→ 弹出剧情 → POST /api/client/collect {adventureOptionKey} 结算
    └─ 结算并入账（金币/经验/掉落/元宝碎片），状态由 statePatch 更新
桌面/托盘推送: POST /api/battle/idle-collect
离线: 服务端累计（≤12h），下次上线 collect 一次性结算
```

### 4.5 首领挑战流程

```
进 boss 页 → 状态 section bosses/professions 已加载
本地配装/切药剂 → POST /api/professions/supply/equip {supplyType:"bossPotion", itemKey}
推演: POST /api/boss/preview {bossKey, 技能/战术/增益/词缀/定向/材料加成} → {simResult}
挑战: POST /api/boss/challenge {bossKey, ...config}
  → 响应 {battle:{events}}；前端播放战斗动画；结束后从 notices 弹结算
  刷新 sections: maps/bosses/quests/achievements/codex/rankingSeason/profile
世界首领协作: POST /api/boss/assist {bossKey}（每次消耗 1 门票，限次）
  期间 WS 推送 worldInstance 更新（剩余生命/参与数/我的伤害/排名）
```

### 4.6 市场交易流程

```
查看: GET /api/market/orders?scope=...&orderType=sell|buy&sort=...
报价: POST /api/market/equipment-quote|item-quote
出售上架: POST /api/market/create-order {itemType, equipmentId|itemId, amount, currencyType, price}
```

## 5. 接口规范（HTTP）

### 5.1 通用约定

**Base URL**：`https://game.placegame.cn`（同一站点；桌面端经由 `desktopBridge.requestGameApi` 会转发到游戏服）。

**请求头（前端 `ac()` 构造）**：

| Header | 值 |
|---|---|
| `content-type` | `application/json` |
| `x-placegame-client-version` | `0.2.49` |
| `x-placegame-client-platform` | `web` |
| `x-placegame-device-id` | 本地生成（localStorage `place-game-device-id`，20-128 位 `[A-Za-z0-9_-]`） |
| `x-placegame-web-build-revision` | `20260825.1` |
| `x-placegame-response-state` | `full` \| `patch` \| `omit`（按接口类型） |
| `authorization` | `Bearer <sessionToken>`（登录后） |

**响应包裹（JSON）**：`{ ok?, statusCode, error?, data?, state?, statePatch?, changedSections?, sectionEtags? }`

- `ok` 由 HTTP 状态决定；非 2xx 时 `error` 为后端错误文案。
- `data`：接口业务数据。
- `state`/`statePatch`：`responseState=full/patch` 时返回的状态数据。
- `changedSections`：本次操作影响到的状态 section 列表。
- `sectionEtags`：view-sections 返回的各 section 版本号（供增量刷新）。

**状态码 / 错误处理**：
- `426 Upgrade Required`：版本过低，前端提示“必须更新后才能继续游戏”。
- `401/403`：会话无效或已过期（error 含“会话无效或已过期”）→ 前端清 session、弹重新登录。
- `503`/含“维护/停服”：维护模式，自动重连。
- `>=500`：服务器异常，自动重试。

**统一变更语义**：除明确标注 GET 外，**本游戏几乎所有业务操作均为 POST**（含预览、查询带参、报价等），这是服务端 `responseState` 状态补丁设计决定的；只有纯列表/快照读取（bootstrap/catalog/idle-summary/activity-logs/announcements/users/list/chat/world/npc-shop/items/market/my-orders/coin-pusher/view/lottery/view/craft/recipes）用 GET。

### 5.3 WebSocket 协议

- 握手：`POST /api/auth/ws-ticket`（Bearer 鉴权）→ `{ticket}` → `ws(s)://host/ws?ticket=<t>&clientVersion=<v>&clientPlatform=web&webBuildRevision=<r>`。
- 客户端 → 服务端消息（JSON）：
  - `{"type":"market:subscribe"}` / `{"type":"market:unsubscribe"}`（进入/离开市场视图）
  - 其他事件：`{"type": "<event>", "data": {...}}`（`sendMapEvent`，桌面端向服务端推送地图/战斗事件）
- 服务端 → 客户端：
  - 状态补丁（state patch，前端 diff 后合并 + 按需 view-sections）
  - 世界聊天新消息 / 撤回
  - 世界首领实例更新（剩余生命、协作状态）
  - 市场订单推送（订阅时）
- 断线重连：指数退避 + 状态机（online / reconnecting / degraded / offline / maintenance / server / network）；WS 不可用时自动切轮询。

## 6. 客户端内置配置（数值参考，服务端可覆盖）

**收益 / 定时**：
- 离线/在线收益累计上限：12 小时（`idleRewardCapacityHours`）。
- 收益预览推送间隔：15s 定时、距上次 >35s 时刷新；市场订单轮询 30s；首领轮询 15s；公告轮询 60s。（前端常量 `Yj=15s, Qj=35s, Gj=30s, Ij=15s, Vj=60s`）
- 时间基准：北京时间，`kj = 480min`（UTC+8），每日重置按北京日期；公会补给北京时间 12:00 补货。

**街机**：
- 统一金币档位：100 / 500 / 1000 / 2500 / 5000，步进 100（默认 500/500/500/100）。
- 老虎机：`rates {triple 2%, pair 28%, anyWin 30%, noWin 70%}`；大奖 巨龙 20000、王冠 12000、宝石 8000、宝箱 5000、幸运草 4000、长剑 3500、药剂 2500、骷髅 2000、史莱姆 1500；对子 1100；免费 1 次，付费上限 20 次。
- 翻牌寻宝：6 牌 2 陷阱；奖励 400/700/1200/1900；首翻安全率 66.67%，全程安全 6.67%，初始塌方 33.33%；免费 1 次，付费上限 8 次。
- 21点：庄家 17 停牌；自然21点 2.5x / 胜 2x / 平 1x；免费 1 次，付费不限。
- 推币机：免费 3 次；5 槽 × 6 容量；全服目标 300 次 → 2000 金币；公会里程碑 40/100/160 → 500/900/1500；代币掉率 金币 72% / 皇冠币 14% / 公会币 8% / 全服币 6%。

**大乐透**：前区 01-15 选 5、后区 01-04 选 2；一等奖 5+2（60%）、二等奖 5+1、三等奖 12%、四等奖 8%；单人每期 100 张上限。

**保底**：击杀每 500 次保底 2 元宝碎片；碎片 100:1 合成；世界首领单场 ≤140 有效碎片、个人/地图首领每日共享 ≤200。

**战力规则**：综合战力由短板主导，强项最多额外贡献短板的 25%。

**市场**：绑定不可交易；购入后转售锁定期；转售手续费更高；回收按参考价 20%。

## 7. 附录：状态 section 与视图映射

前端按当前视图懒加载 sections（`view-sections`），视图 → sections 映射：

| 视图 | 加载 sections |
|---|---|
| overview（主页） | maps, skills, rankingSeason, navigation, profile |
| maps | maps（+config 类） |
| inventory（背包/角色） | profile, rankingSeason, marketAccess |
| skills | skills |
| market（市场） | marketAccess（+marketOrders，订阅推送） |
| boss（首领） | bosses, professions |
| ranking | rankingSeason |
| daily（活动中心） | quests, achievements, codex, arcade |
| professions（副职） | professions |
| guild（公会） | maps, bosses, quests, achievements, rankingSeason, navigation, profile, guild |
| logs（日志/邮件） | tradeLogs, riskEvents, currencyLogs, craftLogs, notices, mails, daily, guildDaily, retention, profile |

关键 section 内容：
- `profile`：玩家（nickname/job/level/exp/power/gold/rareCoin/rareCoinFragment/rebirthCount/currentMap/装备/背包/套装…）+ expForNextLevel + maxLevel + equipmentSets。
- `navigation`：活动可领取计数等角标。
- `rankingSeason`：`seasonKey "season_1"`、bossKills、称号、奖励、赛季起止。
- `daily`：`{key: 北京日期, collectCount, bossCount, bossRareCoinFragments, enhanceCount, decomposeCount, marketListCount, marketBuyCount, killCount, claimedActivity[]}`。
- `arcade`：各小游戏当日免费/付费次数、推币机进度、开奖结果等。
- `retention`：签到（lastClaimedKey/streak/totalClaims/claimedKeys）+ pity 保底计数器。
- `professions`：`{schemaVersion:3, selectedProfessionKey, progresses{herbalism|fishing|cooking|alchemy}, queue[], progressSeconds, lastSettledAt, supplies{foodKey, foodRemainingSeconds, foodActivatedAt, bossPotionKey}}`。
- `guild`：name/level/contribution/totalContribution、仓库、基金、公告、成员、需求、祝福、增益、里程碑。
- `items` / 品质：品质 key `white/green/blue/purple/orange/red/gold`；物品分类 `material/skill_book/consumable/special/equipment`；部位 key 见 3.5。
- 动态补丁频繁落在 sections：`marketOrders`（成交推送）、`worldInstance`（世界首领实例）、`world-chat`（新消息，独立于 section）。
